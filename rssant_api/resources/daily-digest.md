# 每日精选

你的任务：每天从用户的蚁阅订阅里挑出最值得读的几篇，写成一份 Markdown 精选。用户每天只看这一份。

这份文档是给你执行用的，不要把流程原文复述给用户；用户要看的是精选本身。

## 什么时候执行

- 用户说“今天有什么值得看的”“帮我读一下今天的订阅”“来一份每日精选”。
- 用户设置了每天定时执行。

执行前先读接口说明（提示词里的第一个链接），按里面的字段和令牌调用；不要猜接口。

调用接口用 Node 或 Python 写代码执行：Node 用 fetch，Python 优先 httpx（requests 较老、问题较多，不作为首选）。不要用 curl 命令拼接。代码里处理 JSON、重试和写文件更可靠；下面的请求体直接用代码发送。

## 流程

### 1. 取候选

```
POST /story.query_recent
{"days": 1, "unread_only": true, "limit": 200, "per_feed_limit": 3}
```

- 默认最近 1 天；用户说几天没看，就把 days 改成对应天数，最多 30。
- 每次运行都重新调用接口，不要复用上一次保存的 candidates.json、contents.json 或文章文件；数据可能已经变了。
- 只基于这次 query_recent 返回的候选写精选；每源最多 per_feed_limit 篇，候选之外的内容不要猜成“刚新增”，需要更多就重新取。
- total 为 0：告诉用户今天没有新内容，结束；不要编造，也不要生成空文档。
- 返回的每篇带标题、订阅、发布时间，按发布时间倒序。返回的 is_read 已经是真实已读（含阅读位置），不要再自己拿 offset 算。
- 一天更新很多时，先按标题和来源筛到 20 篇左右（去掉广告/活动、同一件事、来源太单一），再读正文。

### 2. 读正文

```
POST /story.query_batch
{"storys": [{"feed_id": "…", "offset": 123, "limit": 1}], "detail": true, "content": true, "content_format": "markdown"}
```

- 一次 10–15 篇，串行调用；不要每篇单独请求，也不要去抓原网页。
- 正文已经是 Markdown，直接用来写作。
- content 为空：说明这个源只提供摘要，用 summary 写，并在该篇末尾注明“原文只有摘要”。
- 确实需要全文时，只对单篇调用 story.fetch_fulltext；它慢且可能被源站拒绝，不要批量用。

### 3. 选出 5–8 篇

按这个顺序判断：

1. 有信息增量：新事实、新数据、新观点、可操作的方法。
2. 有深度：讲清来龙去脉，不是标题党或一句话新闻。
3. 和用户相关：默认按“值得广泛阅读”判断；用户说了关注领域就按领域。
4. 来源均衡：同一订阅最多 2 篇；同一主题的多篇合成一条专题，对比不同观点。

不选：广告、软文、纯活动通知、重复内容（同一链接或同一件事）、只有标题没有正文的。

宁可少选，不要凑数；少于 3 篇也正常。发布时间超过 7 天的文章默认跳过，除非用户要看。

### 4. 写成 Markdown

```markdown
# 每日精选 · 2026年11月28日

> 今天筛了 {total} 篇候选，选出 {N} 篇，约 {X} 分钟读完。

## 速览

| # | 标题 | 订阅 | 一句话 |
|---|---|---|---|
| 1 | … | … | … |

## 1. {标题}

**{订阅}** · {作者} · {发布时间，北京时间} · 约 {X} 分钟

**为什么选它**：{一句话说清信息增量，不要空话}

**核心内容**

{500–900 字。忠实原文，把事实、数据、观点和论证讲清楚；保留 1–2 句原文引用；不添加原文没有的结论。技术文章保留关键做法和结论，观点文章保留论证链，资讯保留事实和影响。}

> {原文引用}

[读原文]({原文链接})

## 2. {标题}

……

## 其他更新

- [{标题}]({链接}) — 一句话
- ……

## 今天的共同主题

{可选。2–3 条跨文章观察，只在确实有共同主题时写。}
```

写作要求：

- 每篇不看原文也能读懂。
- 事实、数字、引语都来自原文；不确定的地方写“原文称”。
- 不写“值得一读”“非常精彩”这类空话。
- 时间是北京时间；链接是原文链接。
- 输出 Markdown，不要 HTML；不要贴整篇原文。

### 5. 交付

- 保存为 `每日精选/YYYY-MM-DD.md`；用户指定了目录就用用户的。
- 在对话里给出文件路径和 3–5 条速览，不要把全文再贴一遍。
- 默认不改订阅数据。交付后问用户一次：“要不要把这次选中的文章标为已读？可以只标这次，也可以以后都标 / 都不标。”
  - 用户选“以后都标”或“以后都不标”：记到 `每日精选/偏好.md`（或你的长期记忆）；以后按偏好执行，不再问。
  - 用户选“只这次”：只标这次，不记住。
  - 用户没回复：默认不标；下次交付再问一次。
- 用户确认要标时，先确认范围，再对选中的文章逐篇调用 story.set_read。
- 偏好是用户之前的明确答复；按偏好执行不算未经确认，不要再问（提示词里的“改数据前先问”已经被这个答复覆盖）。

## 定时执行

- 每天固定时间执行一次。
- 开始前先调用一次 `story.query_recent {"days": 1, "limit": 1}` 检查令牌；401 就提醒用户到「用 AI 阅读」重新复制提示词。
- 执行前先看 `每日精选/偏好.md`：里面写了“以后都标”就直接标并告知用户；写了“以后都不标”就不再问。偏好是用户之前的答复，不用再确认。
- 失败时说明原因，不要生成空文件或假内容。
- 保留最近的精选文件，方便用户回看。

## 调整

用户要求改关注领域、每天几篇、每篇多长、输出语言、是否带图或全文时，按用户的要求执行；没要求就用上面的默认值。用户给了自己的技能文档时，以用户的文档为准。
